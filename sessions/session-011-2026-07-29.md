# Session 011 - 2026-07-29

Implemented the reveal-frontier fix for the blog's layout-shift bug left open at
the end of session 010. CLS is now 0 on every route and Lighthouse Agentic
Browsing reaches 100.

## What was done

Followed the implementation checklist in `session-010-cls-diagnosis.md`.

- **Reverted the `content-visibility` attempt** that was sitting uncommitted in
  the working tree. It measured 0.456, worse than the 0.298 in prod.
- **`style.css`**: `.post-entry:not(.is-revealed) { visibility: hidden }`,
  replacing the `content-visibility` block.
- **`app.js`**: added `revealLoaded()`, which walks the stack and reveals the
  contiguous prefix of rendered posts. Called after render, after a failed
  fetch, and after the reading-order toggle reorders the stack.
- **`sw.js`**: `CACHE_NAME` bumped `blog-v11` → `blog-v12`, so users' stale
  cache-first shells are purged promptly.

## Two deviations from the written recommendation

Both found while implementing, neither changes the approach.

- **`revealLoaded` toggles `is-revealed` both ways.** The recommendation only
  ever *added* the class and `break`ed at the first unloaded post. After the
  reading-order toggle that is wrong: reversing the stack can put an already
  revealed post *below* an unloaded one, which then gets displaced when that
  post finally lands. Now it sets a flag and uses
  `classList.toggle('is-revealed', atFrontier)` across every entry, so posts
  hide again when the order moves them behind the frontier.
- **`revealLoaded` is defined above `loadEntry`, not after `entries`.** Function
  declarations hoist within the scope so either position works; above the first
  caller just reads better.
