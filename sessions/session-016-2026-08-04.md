# Session 016 - 2026-08-04

## What happened

Removed the blog's fragment-based scroll-through stack, per user request: they wanted `/dev-tools#a-skill-structure-that-improves-itself` to instead be `/dev-tools/a-skill-structure-that-improves-itself`, with every folder and every file as its own route and no more auto-scroll-to-next-post behavior. Branch `blog-homepage` (session 015), still off `dev`.

Previously a section page rendered every post in it as one continuous scroll-through stack, addressed by URL fragment (`/{section}#{post-slug}`), with `IntersectionObserver` lazy loading and a "reveal frontier" (`revealLoaded()`) that kept CLS at zero by only revealing a post once it and everything above it had rendered. That entire model is gone.

**`app.js`**: `parseBlogPath()` no longer reads `location.hash`. It now takes the full URL path and the loaded manifest, and checks whether the last path segment is a post slug within the section formed by everything before it - if so, that's a post page; otherwise the whole path is a section (table of contents). This means the manifest has to load before routing can be resolved, unlike before. A post page now renders exactly one post, standalone, fetched directly with no stack, no lazy loading, no reveal-frontier bookkeeping (`is-loaded`/`is-revealed`), and no reading-order toggle (`#sort-toggle`) - none of that machinery makes sense with only one post ever in the DOM. In-page heading anchors (`#h-...`) still work, natively, since they're just ids on the single already-loaded page.

**`section.html` / `style.css`**: removed the dead `#sort-toggle` button markup and its CSS, the reveal-frontier `.post-entry:not(.is-revealed) { visibility: hidden }` rule, the `.post-placeholder` styling, and the now-unused `.post-meta h2` rule (post pages now show the title via `#section-title` in the header, same element the section TOC uses for its own name).

**`build.js`**: sitemap now emits one URL per post (previously only per section, since posts weren't separately addressable), each with its own `lastmod` from the post's date.

**`_redirects`**: only the comment changed - the existing `/*  /section  200` catchall already worked for any path depth, so no rule changes were needed, only the client-side parser.

**`content/test/`**: this fixture set existed specifically to test the old fragment/scroll-stack/reading-toggle behavior (deep links landing mid-stack, cross-post fragment jumps, the reading-order toggle reversing the stack). Asked the user whether to leave it, rewrite it, or delete it - they chose rewrite. Updated `navigation-modes`, `ordering-and-dates`, both nested posts, and one link in `kitchen-sink` to describe and exercise the new per-route model instead (real post-to-post links, section-TOC sort order, multi-segment path parsing at 3 and 4 levels deep). `images-and-media` needed no changes.

**`CLAUDE-blog.md`**: rewrote the routing bullet, replaced the "Reveal frontier" subsection with a "Routing: every folder and post is its own route" subsection explaining `parseBlogPath()` and why the old machinery is gone, fixed the heading-id-prefix rationale (no longer about fragment collision, just a cheap uniqueness guarantee), and updated the "SEO ceiling" known issue to "mostly resolved" (real per-post URLs and per-post `<title>`/meta description now exist; the remaining gap is that content is still rendered client-side, not emitted as static HTML).

**Verified locally** with `npx wrangler pages dev . --port 8080`, in the user's real Chrome: the exact URL from the request (`/dev-tools/a-skill-structure-that-improves-itself`) renders that post standalone; the section TOC (`/dev-tools`) links to real post routes; a single-post section (`/recipes`) works; nested sections 3 and 4 segments deep (`/test/nested/nested-post-one`, `/test/nested/deeper/deep-post`) correctly split section-vs-post; the old fragment URL (`/dev-tools#a-skill-structure-that-improves-itself`) degrades gracefully to just showing the section TOC rather than erroring.
