## Decisions and reasoning

- **Collapse-to-one-project over inline highlighting**: clicking a project hides
  everything else (other projects, section headings, the intro line) rather than just
  marking the clicked item active among visible siblings - user's explicit ask, "zooms
  in" the page to that project's content.
- **Filtering is project-selection only, no independent tag concept**: removing the
  Filter button/tag-picker modal and stripping non-project tags means "active tag" and
  "selected project" are now the same thing everywhere in the code - simpler than
  maintaining two parallel filtering mechanisms for what turned out to be the same UI
  need.
- **Reconstructed URL over `history.back()` for the post-page back button**: a post can
  be reached by direct link/refresh/new tab with no usable history; the tag filter is
  fully described by the URL already, so reconstructing `/?tag=x` from the post's own
  tag is correct in every case, where `history.back()` only works for the one path of
  clicking through in the same tab.
- **No prev/next bottom nav for posts with no project tag**: a standalone post (recipe,
  skill note, screenshot story) doesn't belong to a group, so there's nothing to page
  within - explicit user decision over "still step through non-project posts as their
  own implicit group."
- **`--space-*` scale added but scoped, not swept site-wide**: applied to the
  homepage-specific rules the review flagged plus the one stray px value found
  elsewhere; did not do a full site-wide unit audit outside what was actually reviewed.
