## Renderer bug found: ordered lists break on blank lines between items

**Symptom.** A numbered list written with blank lines between items renders as N separate `<ol>` elements, one per item, so every step displays as "1." instead of 1..10. Confirmed visually in the browser, not just in the DOM.

**Repro.** In any post markdown:

```
1. First step.

2. Second step.
```

Renders two `<ol>`s, both starting at 1. Removing the blank lines gives one `<ol>` with correct numbering. Verified: 10 `<ol>` elements before, 1 after, same content.

**Why it matters.** This is loose-list markdown, which every standard parser (CommonMark, GitHub) handles correctly by emitting a single list with `<p>`-wrapped items. Ours does not, and the failure is silent: the markdown looks right in an editor, and the page looks plausible until you notice every step is numbered 1. Any recipe, tutorial, or how-to with paragraph-length steps will hit this, and blank-line-separated items is the more natural way to write them.

**Workaround used.** The ramen post writes all 10 steps with no blank lines between them. Works, but it makes long steps harder to read and edit in source, and the next person writing a numbered list will hit the same thing.

**Where to fix.** The list handling in `app.js`'s markdown renderer. The paragraph/blank-line splitting runs before or across list detection, so a blank line terminates the list rather than marking it loose. A proper fix groups consecutive list items across blank lines into one list and wraps each item's content in `<p>` when the list is loose. The same bug almost certainly affects unordered lists, where it is invisible because bullets do not number.

Not fixed this session to keep the change to content only. Worth doing before more list-heavy posts land.
