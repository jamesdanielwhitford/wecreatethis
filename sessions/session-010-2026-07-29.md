## Renderer bugs fixed (commit 7a8cf06)

All were visible in the live post `dev-tools/how-to-write-sick-loops-in-claude-code`:

- **Bold-led lines never wrapped in `<p>`.** The paragraph pass skipped any
  line starting with a tag, but bold ran first, so `**What it is:** ...`
  became a line starting with `<strong>` and was skipped. Adjacent lines then
  merged into one run of text. 22 paragraphs in the published post were
  affected. Fixed by skipping only real block-level tags.
- **No table support**, though the published post contains a table.
- **No ordered-list support**, also used by that post.
- **Headings had no ids**, so the post's own table of contents was entirely
  dead. Ids are prefixed `h-` so they cannot collide with post slugs, which
  share the URL fragment. Bare anchors (`#1-watch-with-loop`, as hand-written
  in the post) resolve to the prefixed id as a fallback.
- **Titles rendered twice** (manifest `<h2>` plus the body's leading `# H1`).
- **`//` inside URLs highlighted as a comment** in code blocks.
- **Deep links scrolled before posts above the target had loaded**, so the
  target was pushed out of view. Now loads those first. Added a `hashchange`
  listener so in-page TOC links work after load.

Service worker: ported `cleanResponse()` from the root SW (redirect stripping
is mandatory repo-wide and section paths are `_redirects` rewrites), and
`cache: 'reload'` at install so a `CACHE_NAME` bump cannot pre-cache a stale
shell.

## Dark mode + accessibility/SEO (commit 733bca8)

- **System dark mode, no toggle.** `style.css` moved to custom properties with
  a `prefers-color-scheme` block. Scoped to the blog only by choice; the rest
  of the site is untouched. Paired `theme-color` meta tags.
- **Contrast fixed.** `#888` was 3.54:1, below WCAG AA. Now `#6b6b6b` light /
  `#9a978e` dark, both above 4.5:1, plus a darkened code-comment token.
- **`robots.txt` added.** It did not exist, so Cloudflare's SPA fallback served
  **HTML** to crawlers. A real production bug, not just a Lighthouse nit.
- **`blog/sitemap.xml`** generated by `build.js`, one URL per section with
  lastmod from the newest post. Referenced from `robots.txt`, passed through
  `_redirects`.
- **`<main>` landmark** on both pages; static meta descriptions, with section
  pages filling theirs from the manifest at runtime.
- **`build.js` validates frontmatter**: warns on non-`YYYY-MM-DD` dates,
  non-numeric `order` (now coerced to `null` instead of `NaN` poisoning the
  sort), and truthy-but-not-`"true"` `draft` values that would silently
  publish. Verified all three fire with a throwaway probe post, then deleted it.

## Image handling (commit b5aa41d)

`build.js` now reads intrinsic dimensions straight from the image file header
(PNG, GIF, JPEG parsed by hand, no dependencies) and records them per post in
the manifest. The renderer emits `width`/`height` so the browser can reserve
the right aspect-ratio box.

Non-obvious: the attributes alone did nothing, because the CSS had
`width: auto`, which discards the aspect-ratio box the attributes establish.
Removing it is what made them work. Also dropped `max-height: 80vh`, which
stretched tall images once width followed the ratio.

## llms.txt + shell revalidation (commit ba9a234)

- **`llms.txt` added**, the last remaining Lighthouse failure. Same failure mode
  as `robots.txt`: absent file, so the fallback served HTML, which the audit
  reported as *malformed* rather than *missing*. App links were checked against
  the repo, `pomodoro` and `towersofhanoi` are listed in CLAUDE.md but do not
  exist on disk, so they are deliberately not linked.
- **Shell is now stale-while-revalidate.** It was cache-first with no
  revalidation, so a visitor could sit on an old `app.js` indefinitely while
  picking up new CSS. That is exactly what happened on Safari after the second
  deploy: new dark mode, old renderer, so tables and images did not render and
  there were no console errors. Both pages now load the shared `/sw-toast.js`
  and it is in `ASSETS`. Cache `blog-v11`.

## UNRESOLVED: layout shift on section load

This is the open thread and the reason to start a new session.

Lighthouse on live `/blog/test` reports **CLS ~0.298**, well above the 0.1
threshold. A `PerformanceObserver` attributes essentially all of it to one
element, e.g. `ARTICLE#navigation-modes` going from top=547,height=276 to
top=0,height=0.

It is a **race, not a caching artifact**: on a fast local connection it measures
~0.001, but under Slow 4G throttling it reproduces at ~0.2977, matching prod.
Posts finish loading at different times and the staggering causes the shift.

Four attempts, none successful:

1. `min-height: 60vh` (then `8rem`) on the placeholder. Fails because any
   reserved height is a guess, and a post rendering *shorter* than the guess
   collapses, which is itself a shift.
2. Removing the reservation entirely. Fails because posts then grow from zero
   and push every sibling below them down.
3. Inline `style="min-height:70vh"` written into the `innerHTML` string so it
   exists in the first paint, cleared on render. Worked locally on a fast
   connection (0.0011) but failed on prod/throttled. Diagnostic showed
   `reservedInMarkup: [null, "", "", "min-height:70vh"]` - posts 2 and 3 had
   already rendered and cleared their reservation while post 4 was still
   pending, and post 3 collapsing 276px→0 produced the shift.
4. `content-visibility: auto` + `contain-intrinsic-size: auto 600px` on
   `.post-entry:not(.is-loaded) .md-content`, with JS adding `is-loaded` on
   render. **Currently in the working tree, uncommitted and unverified** - a
   stale service worker kept serving old `app.js` during measurement, so
   `is-loaded` was never applied and the number measured old code.

A Fable subagent was launched at the end of the session to diagnose this
properly. Its report was not yet returned when the session closed. **The next
session should start from that report.**

### Testing gotcha that cost real time

`blog/sw.js` caches `app.js`/`style.css` and (until commit ba9a234) never
revalidated, so edits frequently did **not** take effect on reload and
measurements silently reflected old code. This invalidated several
measurements before it was spotted.

To measure reliably, defeat the SW:

```js
// as navigate_page initScript
Object.defineProperty(navigator, 'serviceWorker', { get: () => undefined, configurable: true });
```

and confirm the code under test is actually running by checking for a known new
substring in the fetched `app.js`.

## Deferred, deliberately

- **Static HTML generation for SEO.** The structural limit is unchanged: posts
  live behind `#fragment` URLs within one section page, so a search result or
  social card can only ever point at a section, never an individual post.
  Lighthouse SEO 100 is mechanical checks passing, not this being solved.
  `build.js` already parses every post, so emitting per-post HTML with real
  title/meta is viable and fits the zero-dependency philosophy.
- **Image optimisation in the build.** Worth it for payload size, but needs a
  dependency or an external tool, and would not have helped the CLS bug.
- **JS minification** (~2.3 KiB) - conflicts with the no-build-step approach.
- **Dark mode for the rest of the site** - blog only was a deliberate choice.
